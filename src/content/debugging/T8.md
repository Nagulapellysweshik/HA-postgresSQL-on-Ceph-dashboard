# T8, PgBouncer pool tuning: debugging

## Blockers hit

### B1. Misleading fairness check
- **Symptom:** session mode had the best average (16 ms p50). My first check, "did every client complete ≥ 1 payment?", said 500/500.
- **Diagnosis:** per-client distribution from the ack logs:
  ```bash
  for f in /logs/<run>/acks-*.log; do wc -l < $f; done | sort -n   # then min / p10 / median / p90 / max
  ```
  Session mode: **median 1, max 3 488**. Transaction mode: 388–403.
- **Lesson:** averages and "at least one" checks hide starvation. Look at the distribution.

### B2. Slot exhaustion at pool 40
- **Evidence:** screenshot `t8-a-pool-tuning-part2-slot-exhaustion.png`, `results/raw/t8-a.slots-at-rest.txt`.
- **Symptom:** PgBouncer stuck at ~32 server connections per pod; the analyzer's direct connection → `remaining connection slots are reserved for SUPERUSER`.
- **Diagnosis:** slot breakdown from `pg_stat_activity` → `cnpg_pooler_pgbouncer | postgres | 32`: **PgBouncer's auth_query connections**.
- **Root cause:** 100 − 3 reserved − 32 auth ≈ 65 slots for app traffic.
- **Fix:** the analysis was re-run after the load ended. Recommendation: raise `max_connections` or cap the auth pool.
