# T9, read/write split: debugging

## Blockers hit

### B1. Test couldn't start: pooler-held slots after T8
- **Evidence:** `results/raw/t9-r1.events` (lag 0, bytes 0: no writes ever got in).
- **Symptom:** the first connection (HAProxy → PgBouncer) → `server login has been failing, cached error: remaining connection slots are reserved for roles with the SUPERUSER attribute`.
- **Root cause:** after T8, PgBouncer kept the server connections from the bigger pool (`server_idle_timeout` 600 s) plus 32 auth connections, so the primary was full **with no load**.
- **Fix:** `kubectl -n pg rollout restart deploy/pg-lab-pooler-rw` released them; t9-r2 ran.
- **Lesson:** after a peak, check slot usage before starting new work; set `server_idle_timeout` deliberately.

### B2. Writes slowed by read load on the sync replicas
- **Diagnosis:** commit p50 49 ms (2× normal) with zero reads on the primary. Each commit waits for one of the replicas serving 9 000+ reads/s.
- **Remedy:** a dedicated **async** read replica, or resource isolation.
