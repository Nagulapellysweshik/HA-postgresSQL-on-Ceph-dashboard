# T2, primary crash (direct): debugging

## Blockers hit

### B1. "Is a 24 s failover normal?"
- **Evidence:** `results/raw/t2-r1.operator-log.txt`, `t2-r2.instance-log.txt`, `t2-r3.failover-live.txt`; screenshot `t2-r4-failover-4-pane-live.png`.
- **Diagnosis chain:**
  1. **Operator log:** detection 0.8 s, election 3.6 s, then `Waiting for the new primary to notice the promotion request` for 19 s.
  2. **New primary's instance log:** `Acquiring primary lease` 07:39:17.6 → **`Acquired primary lease` 07:39:33.7** (16 s).
  3. **Lease object:** `kubectl -n pg get lease pg-lab -o yaml` → `leaseDurationSeconds: 15`, and `acquireTime` matches the log.
- **Root cause:** the force-killed primary can't release the CNPG primary lease, so the new one waits for it to expire. That's a split-brain guard working by design.
- **Lesson:** detection and election are seconds; the floor is the lease.

### B2. Evidence destroyed by the next test
- **Symptom:** pg-lab-1's log for run 1 was gone, because run 2 killed that pod.
- **Fix:** capture logs from the **current** primary before the next fault; a live log pane that tees to a file during the run.

### B3. "Force delete" didn't stop the old primary
- **Observation:** acks from the old primary continued **2.5 s** after `--force --grace-period=0` in every run.
- **Lesson:** the API object disappearing ≠ the process being dead. Fencing (lease, WAL receivers down) is what keeps it safe.
