# T6, node (zone) loss: debugging

## Blocker found in pre-flight: HAProxy SPOF next to the primary
The second pre-flight (17:08 IST) found **HAProxy (1 replica) and the Ceph toolbox on the primary's node** (`ip-10-90-173-158`). Stopping it would have measured a ~5 min proxy outage, not database failover. The primary was switched to `pg-lab-3` (`ip-10-90-151-24`) first. Full write-up and fix: [step 09 B4](../../docs/steps/09-haproxy.DEBUGGING.md).

## Blocker: cordon moved the primary before the fault
See the README's third pre-flight finding. The script now aborts if the primary changed between the start and the stop.

## Observations from the run
- **EC2 stop is graceful:** writes continued ~2 min after `stop-instances` until the OS shutdown reached Postgres. For a hard failure, use `--force` or a network cut.
- **The return came in two waves**, identified from Ceph's own ages at 12:24:43 (`mon … quorum a,b,c (age 5m)`, `osd … 3 up (since 2m)`):
  - **A (12:19:24–45):** mon-b rejoined quorum while the node's pods restarted. Writes median 241 tx/s.
  - **B (12:22:16–12:24:30):** osd.1 came up (its pod needed ~3 min after node Ready), a 3 s peering stall, then backfill at ~40% throughput with stale reads spiking.
- **Toolbox on the victim node:** the status loop kept working (`cstat` tolerates errors). The toolbox is a Deployment, so it was rescheduled.
