# T11, rolling minor upgrade: debugging

## Blockers hit

### B1. Rolling upgrade stuck: a replica can't mount its volume
- **Symptom:** the script waited > 25 min. `kubectl cnpg status` → `Waiting for the instances to become active`, Ready 2/3, `pg-lab-2 BadRequest`.
- **Diagnosis chain:**
  1. **Pods:**
     ```bash
     kubectl -n pg get pods -l cnpg.io/podRole=instance -o 'custom-columns=…IMAGE…'
     ```
     pg-lab-2 is `Pending` on **18.7**; pg-lab-1 (primary) and pg-lab-3 are still on 18.6. So CNPG did the right thing: one replica first, and it waits.
  2. **Events:**
     ```bash
     kubectl -n pg get events --sort-by=.lastTimestamp
     ```
     → `FailedMount … failed to fetch monitor list using clusterID (rook-ceph): missing configuration for cluster ID "rook-ceph"`
  3. **CSI config:**
     ```bash
     kubectl -n rook-ceph get cm ceph-csi-config -o jsonpath='{.data}'
     ```
     → `{"config.json":"[]"}` (empty); `rook-ceph-csi-config` → `[]`.
  4. **CSI CRs:**
     ```bash
     kubectl -n rook-ceph get cephconnections.csi.ceph.io,clientprofiles.csi.ceph.io
     ```
     → **no ClientProfile**; the CephConnection is only **96 min old** (recreated).
  5. **ceph-csi operator log:** `Failed loading ClientProfile … ClientProfile reconciliation failed` (10:09, 10:25 UTC).
  6. **Rook operator log** (`results/raw/t11-r1.rook-operator-csi.txt`): at **08:57:37 UTC**, when T5 resumed the Rook operator, Rook recreated the CephConnection and the `clientProfile default CR` and saved the mon endpoints. So CSI was healthy then. The CephConnection has **no ownerReferences**.
- **Root cause (partly open):** the ClientProfile was deleted some time after 08:57:52, and the CSI config emptied. New RBD mounts fail; already-mapped volumes (primary, pg-lab-3) keep working. That's why nothing showed for 70 minutes. **T5's operator pause/resume is the prime suspect; the exact deleting actor isn't identified yet.**
- **Impact while stuck:** the cluster ran on 2 of 3 instances (primary + one sync standby). Writes continued, but one more failure would block writes (`dataDurability: required`).
- **Fix applied (≈10:51 UTC):** `kubectl -n rook-ceph rollout restart deploy/rook-ceph-operator`. Within 2 min:
  - `clientprofile.csi.ceph.io/rook-ceph` was **recreated** (age 115 s);
  - `ceph-csi-config` was **repopulated** with `clusterID rook-ceph`, monitors `172.20.229.163:3300, 172.20.205.221:3300, 172.20.75.107:3300` and the RBD secret references (`results/raw/t11-r1.stuck-diagnosis.txt`).
  - The CSI node plugins read that ConfigMap through a volume, so the kubelet's next mount retry (after ConfigMap propagation, ~1–2 min) can succeed. - **Result:** pg-lab-2 mounted and started on 18.7. CNPG then restarted pg-lab-3, then the primary in place (16.5 s write outage at 11:00:28). Cluster healthy, all on 18.7, 0 acked lost over 5.08 M payments.
- **Lessons:**
  1. A fault test can pass and leave latent damage; re-validate the storage path after every chaos test.
  2. CNPG's rolling upgrade is safe by design: it stopped after the first replica and never touched the primary.
  3. Read events before logs. `FailedMount` named the exact layer in one line.
